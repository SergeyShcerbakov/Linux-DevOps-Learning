### 1. Процесс (process) — это запущенный экземпляр программы.  
`Программа → запуск → Процесс`
<details>

Например: python app.py  
app.py — программа/файл, а запущенный python app.py — процесс.

Каждый процесс имеет свой PID (Process ID) — уникальный идентификатор процесса.

</details>

# 2. PID и PPID

<details>
PID (Process ID)— ID самого процесса.  

PPID (Parent Process ID) — индификатор родительского процесса.  

```
ps                - посмотреть
ps aux            - посмотреть конкретнее 
ps aux | grep vim - gпосмотреть и найти процесс vim
```
Правильно:
#Всё ниже — потомки (descendants) systemd.

```
А непосредственно под ним — его дочерние процессы.
systemd
   │
   ├── sshd          ← child systemd
   │    └── bash     ← child sshd
   │         └── vim ← child bash
   │
   └── nginx         ← child systemd
```

</details>

# 3. Основные команды
<details>

```
| Команда      | Что делает                                  |
| ------------ | ------------------------------------------- |
| ps           | показать процессы                           |
| ps aux       | показать все процессы                       |
| ps -ef       | процессы + PPID                             |
| top          | процессы в реальном времени                 |
| htop         | удобный интерактивный `top`                 |
| pgrep name   | найти PID по имени                          |
| pidof name   | найти PID программы                         |
| kill PID     | отправить сигнал процессу                   |
| pkill name   | отправить сигнал по имени                   |
| jobs         | процессы текущего shell                     |
| fg           | вернуть job на передний план                |
| bg           | запустить остановленный job в фоне          |
| nohup        | продолжить работу после выхода из терминала |
```

top показывает процессы динамически в реальном времени, а htop позволяет интерактивно работать с ними

</details>

# 7. Сигналы
<details>
kill на самом деле означает не обязательно «убить».  

Он отправляет сигнал процессу. По умолчанию kill PID отправляет SIGTERM.  

`kill PID`

```
kill 1234     - Нормальное завершение  
kill -15 1234 - явное завершение  
kill -9 1234  - если процесс не реагирует
```

Основные сигналы

| Сигнал    | Номер | Значение                |
| --------- | ----: | ----------------------- |
| `SIGTERM` |  `15` | нормально завершить     |
| `SIGKILL` |   `9` | принудительно завершить |
| `SIGSTOP` |  `19` | остановить              |
| `SIGCONT` |  `18` | продолжить              |
| `SIGHUP`  |   `1` | hangup                  |
| `SIGINT`  |   `2` | прерывание (`Ctrl+C`)   |

SIGKILL — крайний вариант. Процесс не может его обработать и корректно завершить свою работу.

</details>

# 9. jobs
<details>
jobs - Посмотреть фоновые задачи текущего shell:  

Например:  
```
[1]+ Running    ping google.com &
[2]- Stopped    vim test.txt
```
Важно: jobs показывает именно jobs текущей оболочки, а не все процессы системы.

</details>

# 11. Ctrl+Z
<details>

```
Запустили:
ping google.com

Нажали:
Ctrl+Z

#Процесс не завершился — он остановлен.

Проверяем:
jobs

Получаем:
[1]+ Stopped    ping google.com

Продолжить в фоне:
bg %1

Вернуть на передний план:
fg %1
```

</details>

# 12. nohup
<details>

Если запустить: `python app.py &`  

и закрыть SSH/терминал, процесс может завершиться.  

Для запуска, который должен пережить закрытие терминала: `nohup python app.py &`  

nohup предназначен для запуска команды так, чтобы она игнорировала SIGHUP (hangup).  

По умолчанию вывод может записываться в: nohup.out
</details>

# 13. Состояния процесса
<details>
В ps можно увидеть: STAT  

| Код | Значение                          |
| --- | --------------------------------- |
| `R` | Running / Runnable                |
| `S` | Sleeping                          |
| `D` | Uninterruptible sleep, обычно I/O |
| `T` | Stopped                           |
| `Z` | Zombie                            |

R → процесс работает  
S → ждёт событие  
T → остановлен  
Z → zombie  

Эти состояния описаны в ps как стандартные коды состояния процесса.

</details>

# 14. Zombie
<details>

Zombie — процесс уже завершился, но его родитель ещё не забрал информацию о его завершении.  

```
Parent
   │
   └── Child → завершился
             ↓
          Zombie
```
Важно:
Zombie — это не работающий процесс, который продолжает есть CPU.  

Он уже завершился, но запись о нём ещё остаётся в таблице процессов.  

</details>
