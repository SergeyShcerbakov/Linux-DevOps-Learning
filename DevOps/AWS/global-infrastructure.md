## 1. What is AWS Global Infrastructure?

<details>
**AWS Global Infrastructure** — глобальная инфраструктура Amazon Web Services, состоящая из географических регионов, зон доступности и точек присутствия, которые обеспечивают работу облачных сервисов по всему миру.

Основные компоненты:
- **Region** — географический регион.
- **Availability Zone (AZ)** — зона доступности внутри региона.
- **Edge Location** — точка присутствия для доставки контента и ускорения сетевых запросов.
</details>

## 2. Region

<details>

**Region** — отдельная географическая область, в которой AWS размещает инфраструктуру для предоставления облачных сервисов.

Примеры названий регионов:
- `us-east-1` — US East (N. Virginia).
- `eu-west-1` — Europe (Ireland).
- `eu-central-1` — Europe (Frankfurt).

Каждый регион содержит несколько Availability Zones.

### Why choose a Region?

При выборе региона учитывают:

- **Latency:** расстояние до пользователей и задержку сети.  
- **Compliance:** требования законодательства к хранению и обработке данных.  
- **Service Availability:** не каждый сервис доступен во всех регионах.  
- **Cost:** цены на некоторые ресурсы различаются между регионами.  
- **Disaster Recovery:** возможность организовать резервную инфраструктуру в другом регионе.  

**Пример:** если основная аудитория приложения находится в Европе, можно выбрать европейский регион, чтобы уменьшить задержку и учитывать требования к данным.

Важно: регион — это не одна серверная комната, а географическая область с собственной инфраструктурой AWS.

</details>

## 3. Availability Zone (AZ)

<details>

**Availability Zone (AZ)** — изолированная группа одного или нескольких дата-центров внутри конкретного региона AWS.

Каждый регион имеет несколько AZ. Зоны проектируются так, чтобы сбой в одной зоне с меньшей вероятностью повлиял на другие зоны.

Особенности:
- Каждая AZ относится к определённому региону.
- Между AZ предусмотрены высокоскоростные частные сетевые соединения.
- AZ используются для построения отказоустойчивой инфраструктуры.
- Размещение ресурсов в нескольких AZ помогает пережить сбой одной зоны.

### Example

Допустим, приложение работает на двух серверах:

- EC2-A находится в `eu-central-1a`.
- EC2-B находится в `eu-central-1b`.

Если первая AZ становится недоступной, сервер во второй AZ может продолжить работу — при условии, что приложение, балансировка, данные и остальные компоненты также правильно спроектированы для отказоустойчивости.

Важно: простое создание двух серверов не гарантирует автоматическое переключение. Для этого могут понадобиться Load Balancer, репликация данных и другие механизмы.

</details>

## 4. Edge Location

<details>

**Edge Location** — точка присутствия сети AWS, используемая для доставки контента и ускорения некоторых сетевых операций ближе к конечным пользователям.

Edge Locations используются, в частности, сервисом Amazon CloudFront — CDN (Content Delivery Network).

### How it works

1. Пользователь запрашивает изображение, видео или другой контент.  
2. Запрос обслуживается ближайшей подходящей точкой присутствия, если это возможно.  
3. Если контент уже закеширован, он может быть передан из кэша.  
4. Если контента в кэше нет, CloudFront может получить его от исходного сервера и сохранить для последующих запросов — согласно настройкам кэширования.  

Преимущества:  
- уменьшение задержки при доставке кэшируемого контента;  
- снижение нагрузки на исходный сервер;  
- ускорение загрузки сайтов и медиафайлов.  

Важно: Edge Location не является просто ещё одной AZ и не предназначена для обычного размещения виртуальных серверов EC2.

</details>

## 6. Multi-AZ Architecture

<details>

**Multi-AZ** — архитектурный подход, при котором ресурсы размещаются или данные реплицируются между несколькими Availability Zones для повышения доступности и устойчивости к сбоям.

Пример:

- AZ-A: сервер приложения.
- AZ-B: дополнительный сервер приложения.
- Load Balancer: распределяет запросы между доступными серверами.
- База данных: настроена на подходящий механизм репликации и восстановления.

Если одна зона становится недоступной, оставшаяся инфраструктура может продолжить обслуживать пользователей.

Преимущества:
- повышение доступности;
- снижение риска простоя при отказе одной AZ;
- возможность обслуживания и восстановления отдельных компонентов.

Недостатки:
- дополнительные расходы;
- необходимость правильной настройки приложения и данных;
- более сложная архитектура.

В классической конфигурации RDS **Multi-AZ DB instance** развёртывается в 2 Availability Zones (AZ):  
Primary — основная база данных, которая обслуживает чтение и запись.  
Standby — синхронная резервная копия в другой зоне доступности.  

Есть и другой вариант: **Multi-AZ DB cluster** — три экземпляра БД в 3 Availability Zones: один Writer и два Reader. Они могут обслуживать чтение, а при отказе Writer один из Reader может быть повышен до Writer 

2 AZ   Multi-AZ DB instance   - Основная БД + резервная Standby. Standby не обслуживает обычные запросы чтения.  
3 AZ   Multi-AZ DB cluster - Один Writer + два Reader. Поддерживает чтение с реплик и автоматическое переключение.  

</details>

## 7. Multi-Region Architecture

<details>

**Multi-Region** — архитектура, в которой ресурсы размещаются в нескольких регионах AWS.

Может использоваться для:  
- Disaster Recovery (DR);  
- восстановления после масштабного регионального сбоя;  
- уменьшения задержки для пользователей в разных частях мира;  
- выполнения некоторых требований к географическому размещению данных.  

Multi-Region обычно сложнее и дороже, чем Multi-AZ. Необходимо отдельно проектировать репликацию данных, маршрутизацию трафика, переключение и согласованность данных.

**Запомни:** Multi-AZ защищает от ряда сбоев на уровне зоны доступности, а Multi-Region позволяет строить защиту от сбоев на уровне региона.

</details>

## 8. Important Concepts

<details>
- **Latency:** время задержки при передаче данных.  
- **High Availability (HA):** обеспечение доступности сервиса.  
- **Fault Tolerance:** способность продолжать работу при определённых отказах.  
- **Disaster Recovery (DR):** восстановление системы после серьёзного сбоя.  
- **CDN:** сеть распределённых точек доставки контента.  
- **Caching:** временное хранение данных для ускорения повторных запросов.  
</details>

g# Summary
<details>
- **Region** — географическая область AWS, содержащая несколько AZ.  
- **Availability Zone** — изолированная группа дата-центров внутри региона.  
- **Edge Location** — точка присутствия для доставки контента и ускорения сетевых операций.  
- **Multi-AZ** — повышение устойчивости к сбоям на уровне зоны.  
- **Multi-Region** — архитектура для сценариев, требующих работы в нескольких регионах, в том числе Disaster Recovery.  

Короткая формула для запоминания:

**Region = где размещаем ресурсы.**

**AZ = как повышаем отказоустойчивость внутри региона.**

**Edge Location = как доставляем контент ближе к пользователю.**
</details>
