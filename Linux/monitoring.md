# Linux Monitoring — мониторинг системы

 Мониторинг — это наблюдение за состоянием Linux: загрузкой процессора, использованием оперативной памяти, дисков, сети и работой процессов.  

Цель — понять, что происходит с системой, какой ресурс перегружен и какой процесс вызывает проблему.  

# 1. Основные команды
<details>

```
top        - Процессы и нагрузка в реальном времени

htop       - Удобный интерактивный монитор процессов

ps         - Список процессов на данный момент

free -h    - Использование оперативной памяти

df -h      - Свободное место на файловых системах

du -sh     - Размер каталога или файла

uptime     - Время работы и средняя нагрузка

vmstat	   - Состояние памяти, CPU и процессов

iostat	   - Нагрузка на диски

ip -s link - Сетевая статистика интерфейсов

journalctl - Просмотр системных журналов
```

</details>

# 2. Мониторинг CPU и процессов

<details>

top — процессы в реальном времени

Показывает загрузку CPU, память, процессы и их потребление ресурсов.

Основные поля:
```
PID — идентификатор процесса.

USER — владелец процесса.

%CPU — использование процессора.

%MEM — доля оперативной памяти.

COMMAND — имя команды.

Полезные клавиши внутри top:

P — сортировка по использованию CPU.

M — сортировка по памяти.

1 — отображение загрузки отдельных ядер CPU.

q — выход.
```

htop — интерактивный монитор  
Аналог top, но с более удобным интерфейсом. Можно выбирать процессы, сортировать их и отправлять сигналы  

### ps

ps     - список процессов
ps -ef - показывает процессы, запущенные в системе.

</details>

# 3. Мониторинг оперативной памяти (RAM)

free -h - показывает использование RAM и Swap.

<details>

Показывает использование RAM и Swap.

Основные поля:
```
- total — общий объём памяти.

- used — используемая память.

- free — полностью свободная память.

- available — сколько памяти доступно приложениям с учётом возможности освободить кэш.

- Swap — использование дискового пространства в качестве дополнительной виртуальной памяти.
```
На что смотреть: прежде всего на available, а не только на free. Linux использует свободную память для кэширования, и это нормально.
```
ps     - список процессов
ps -ef - показывает процессы, запущенные в системе.
```

</details>

# 4. Мониторинг дисков и файловых систем
<details>

df -h - свободное место
```
Пример:
Filesystem      Size  Used  Avail  Use%
/dev/sda2        50G   40G    10G   80%
```
Если Use% приближается к 100%, на разделе заканчивается место.  

df -h /			- проверить конкретный раздел  
du -sh /var/log - размер каталога  
du -sh ./*		- найти размеры каталогов в текущей директории

Разница:

df — сколько места занято на файловой системе.  
du — сколько места занимают конкретные файлы и каталоги.  

lsblk — диски и разделы, показывает диски, разделы и точки монтирования.
</details>

# 5. Общая нагрузка системы
<details>

```
### uptime

- текущее время;

- время работы системы;

- количество пользователей;

- среднюю нагрузку — load average.
```

Например:  
load average: 0.50, 1.20, 2.00  
Это средняя нагрузка за последние 1, 5 и 15 минут.  

Что означает Load Average?

`Load Average` показывает среднее количество задач, которые выполняются или ожидают возможности работать, включая некоторые задачи в непрерываемом ожидании, например дискового ввода-вывода.  

Ориентироваться нужно на количество CPU-ядер.

Например, на системе с 4 ядрами:

load average: 2.00 — нагрузка примерно на уровне половины вычислительной ёмкости, если задачи CPU-bound.
load average: 4.00 — нагрузка примерно соответствует четырём ядрам.
load average: 8.00 — значительная очередь задач вероятна.

Это ориентир, а не точный процент загрузки CPU: высокая нагрузка может быть связана и с ожиданием диска.
```
nproc - количество логических CPU:
```

</details>

# 6. Расширенный мониторинг
<details>

vmstat 1 - память, процессы и CPU  
1 - обновляет статистику каждую секунду, можно указать инетервал в секундах.  

Полезные поля:

r — задачи, ожидающие CPU.

si, so — обмен данными со Swap.

us — время CPU в пользовательских процессах.

sy — время CPU в ядре.

id — время простоя CPU.

wa — время ожидания ввода-вывода.

Если si и so постоянно ненулевые, система активно использует Swap. Это может указывать на нехватку RAM, но само по себе не доказывает проблему.
```
iostat — нагрузка на диски  
iostat -xz 1 - Показывает статистику дискового ввода-вывода.  
```

</details>

# 7. Мониторинг сети
<details>

ip -s link - Показывает сетевые интерфейсы и статистику передачи данных.  

Основные показатели:
```
RX — принятые данные.

TX — отправленные данные.

errors — ошибки.

dropped — отброшенные пакеты.
```
ss — сетевые соединения  
ss -tuln - Показывает TCP- и UDP-порты, которые прослушиваются.  
ss -tunap - Показывает сетевые соединения и, где доступны права, связанные с ними процессы.  

</details>

# 8. Мониторинг системных журналов
<details>

```
journalctl        - просмотреть системные сообщения.
journalctl -n 50  - последние сообщения.
journalctl -f     - следить за новыми сообщениями.
journalctl -b	  - сообщения текущей загрузки.
journalctl -u ssh - сообщения конкретного сервиса.

В некоторых системах служба называется sshd — название можно проверить через systemctl
```
```
journalctl -p err -b - для поиска ошибок.
dmesg -T             - Показывает сообщения ядра, например об обнаружении оборудования, драйверах и проблемах с устройствами.
```

</details>

# 9. Быстрая диагностика: если Linux тормозит

<details>

```
Симптом					Что проверить

Высокая загрузка CPU 	top, htop, ps aux

Заканчивается RAM		free -h, vmstat 1

Заканчивается место		df -h, du -sh

Медленно работает диск  iostat -xz 1

Высокий Load Average	uptime, top, vmstat 1

Проблемы с сетью		ip -s link, ss -tuln

Ошибки служб или ядра	journalctl, dmesg -T
```

</details>
