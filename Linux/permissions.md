# Permissions
##Contents - Содержание
```
1. chmod                     (команда для управления правами доступа к файлам и каталогам)
2. SUID, SGID, Sticky bit    (специальный бит для файла/каталогов)
3. ACL - Access Control List (расширенные списки прав доступа)
4. lsattr, chattr            (атрибуты файлов)
5. umask                     (маска прав доступа по умолчанию для новых файлов и каталогов)
6. chown                     (команда для изменения владельца и/или группы файла или каталога)
7. chgrp (change group)      (команда для изменения группы-владельца файла или каталога)
```
# Important rule :
```
Права каталога - это что можно делать с объектом внутри.      Example: folder: rwx  
Права файла - это что можно делать с содержимым самого файла.          file:   r--  
```

- `chmod 775 file`- rwx rwx r-x 

## Установка прав в буквенном формате:  
- `chmod u+x file` - Дать владельцу право на выполнение  

- `chmod g-w file` - Убарть у группы право на запись  

- `chmod o+r file` - Дать остальным право на чтение

# 2. SUID, SGID, Stiky bit
<details>

```
SUID        s→ u+s
SGID        s→ g+s
Sticky bit  t→ +t
```
```
4=SUID              4000=SUID       6000=SUID+SGID
2=SGID              2000=SGID
1=Sticky (t-bit)    1000=Sticky     7000=SUID+SGID+Sticky
0=ничего
```
Если нет execute (x)- буква становится заглавной  
- `s>S`
- `t>T`

### #SUID (Set User ID) - специальный бит для файла  

Все новые файлы и папки внутри наследуют группу каталога,а не группу пользователя который их создал.  
При запуске файла с установленными правами SUID программа выполняется с правами владельца файла, а не пользователя который её запустил.  
SUID имеет смысл именно для исполняемых файлов. Для каталогов поведение SUID не используется как повышение прав.  

- `сhmod u+s  file` - добавить специальный бит  
- `chmod 4775 file` - добавить специальный бит  
- `chmod 0775 file` - убрать специальный бит  

### #SGID (Set Group ID)  

Применяется к исполняемым файлам и каталогам.  
Для исполняемого файла: запускается с группой владельца файла  
Для каталога:			новые файлы и каталоги внутри него наследуют группу родительского каталога.  
```
- chmod g+s   file||folder
- chmod 2775  file||folder
- chmod 0775  file||folder
```

```
chmod g+s /shared
и у shared группа:
root developers
То новые файлы внутри /shared будут наследовать группу developers,
независимо от того какой пользователь их создал.
```
SGID на каталоге: новые файлы и каталоги созданые внутри него, наследуют группу этого каталога.  

### #Sticky bit - t  

Применяется к каталогам.  
Пользователи могут создавать файлы в общем каталоге, но не могут удалить или переименовать чужие файлы в этом каталоге.  

- `chmod 1775 folder` - добавить специальный бит  
- `chmod 0775 folder` - убрать t-bit

</details>

# 3. ACL - Access Control List (расширенные списки прав доступа)
<details>

### ACL позволяет дать права конкретному пользователю не меняя owner/group  

```
- getfacl file               - показать ACL файла  
- setfacl -m u:user:rw file  - добавить или изменить ACL для пльзователя  
- setfacl -x u:user file     - удалить ACL для пользователя  
- setfacl -b file            - удалить все ACL из файла  
- setfacl -m g:group:rw file - разрешить группе запись и чтение  
```

```
- mount | grep acl           - чтобы ACL работали, файловая система должна быть смонтирована 
                               с поддержкой ACL.  
```
Этой командой (mount) можно проверить и если будет вывод похожий на это значит ACL включены: /dev/sda1 on / type ext4 (rw,relatime,acl)  
</details>

# 4. File attributes lsatt, chattr
<details>

### Если есть атрибут файла, то даже root не может изменять и записывать.  
### Только root может снять защиту и изменить.  

```
- lsattr file    - посмотреть атрибуты файла
- chattr +i file - добавление атрибута i
- chattr -i file - удаление атрибута i

```

```
- man chattr                        - посмотреть все атрибуты ↓↓↓

- a - append only                   - файл можно только дописывать, нельзя удалять/перезаписывать обычным образом
- i - immutable						- файл нельзя изменить, удалить, переименовать или создать на его месте другой
- e - extent format					- файл испльзует extents для хранения данных, обычно установлен по умолчанию в ext4
- A - no atime						- не обновлять время последнего доступа (atime)
- S - synchronous					- изменения файла на диск записываются синхронно
- d - no dump						- файл не включается в дамп файловой системы
- c - compressed					- файл должен храниться в сжатом виде - поддержка зависит от файловой системы
- j - journaled 					- данные файла должны записываться через журналирование
- T - top of directory hierarchy    - для оптимизации размещения каталогов
- D - synchronous directory updates - изменения каталога записываются синхронно
```

</details>

# 5. umask
<details>

### !!! Но umask:  не даёт права,  а УБИРАЕТ их.  

```
Для  файлов    → 666  
Для директорий → 777  
```

```
Число   Биты    Права
  4     100       r
  2     10        w
  1     1         x
```

```
◆ Для директорий ► 777                                owner
Например umask 731. Для директории: 777-731 = 046     7 - 7 = 0 (---)
 777                                                  group
-731                                                  7 - 3 = 4  (r--)
----                                                  others
 046                                                  7 - 1 = 6  (rw-)
```

```
◆ Для файлов ► 666                                    owner
666 - 731 = 035                                       6 - 7 (---) убирает всё
035 нужно задать права для umask чтобы получить ↓↓↓   group
↪   --- -wx r-x                                       6 - 3 = 3 (-wx)
                                                      others
                                                      6 - 1 = 5 (r-x)
```

</details>

# 6. chown - смена владельца и группы
<details>

### chown (change owner) изменяет владельца файла/каталога и при необходимости его группу.  
### Выполняется команда только с sudo.

```
sudo chown user1 file.txt              - сменить владельца
sudo chown user1:developers file.txt   - сменить владельца и группу
sudo chown :developers file.txt        - сменить только группу
sudo chown -R user1:developers folder/ - Рекурсивно для каталога и всего содержимого
```

</details>

# 7. chgrp — change group
<details>

### chgrp (change group)- команда для изменения группы-владельца файла или каталога.  

```
chgrp developers file           - меняет группу файла, но не его пользователя-владельца.
chgrp -R developers project/    - для каталога со всем содержимым -R — рекурсивно
```

Аналог через chown:  
chown :developers file  

</details>
