# 1. Что такое сеть, клиент и сервер.  

### Network

<details>

**Компьютерная сеть** — это два или более устройства, которые могут обмениваться данными между собой.
```
  Ноутбук
192.168.1.10
     ⮃
  Роутер
Домашняя сеть
     ⮃
  Телефон
192.168.1.11
```

**Internet** - это глобальная система взаимосвязанных компьютерных сетей, которые обмениваются данными с использованием общих протоколов связи, прежде всего семейства TCP/IP.  

**Интернет** — это сеть сетей, объединяющая компьютеры, серверы, смартфоны и другие устройства по всему миру c помощью кабеля, оптики, wifi и другими каналами связи.  

**Типы сетей:**

```
1. Metropolitan Area Network    (MAN)     — городская сеть 
2. Wireless Local Area Network  (WLAN)    — беспроводная локальная сеть 
3. Personal Area Network        (PAN)     — персональная сеть 
4. Campus Area Network          (CAN)     — кампусная сеть 
5. Storage Area Network         (SAN)     — сетевая система хранения 
6. System Area Network          (SAN)     — системная сеть 
7. Passive Optical Area Network (POLAN)   — пассивная оптическая сеть 
8. Local Area Network           (LAN)     — локальная сеть 
9. Wide Area Network            (WAN)     — глобальная сеть 
10. Virtual Private Network     (VPN)     — виртуальная частная сеть 
11. Enterprise Area Network     (EAN)     — корпоративная сеть 
12. Internet Service Provider   (ISP)     — интернет-провайдер, предоставляющий доступ к интернету.
```

</details>

### Client

<details>

**Клиент** — это программа или устройство, которое инициирует запрос к другому участнику сети.  

Примеры клиентов:  
- Браузер Firefox — запрашивает веб-страницу.  
- SSH-клиент — подключается к удалённому Linux-серверу.  
- Команда curl — отправляет HTTP-запрос.  
- Docker-контейнер — может обращаться к другому сервису.  

</details>

# Server

<details>

**Сервер** — это программа, которая принимает запросы от клиентов и предоставляет им данные или услуги.

Например:
- Nginx принимает HTTP-запросы и отдаёт веб-страницы.  
- SSH-сервер принимает подключения для удалённого управления.  
- DNS-сервер отвечает на запросы о доменных именах.  
- База данных принимает запросы приложений и возвращает результаты.  

Серверная программа обычно ожидает подключения на определённом порту.  

Пример: Nginx может принимать HTTP-запросы на порту 80, а HTTPS — на порту 443.  

При этом сервером может быть обычный компьютер, виртуальная машина или Docker-контейнер. Главное здесь — не мощность компьютера, а роль программы в обмене данными.  
```
               Шаг 1. Клиент
Браузер хочет открыть сайт и отправляет запрос.
                     ⬇
               Шаг 2. Сервер
Веб-сервер получает запрос и обрабатывает его.
                     ⬇
               Шаг 3. Ответ
Сервер отправляет страницу, а браузер отображает её.
```
```
Клиент                  Сервер
   |                        |
   |---- Запрос ----------->|
   |                        |
   |<---- Ответ ------------|
   |                        |
```

Обрати внимание: клиент и сервер — это роли, а не обязательно разные типы компьютеров. Один компьютер может одновременно быть клиентом одного сервиса и сервером другого.  

Например, твой Ubuntu может подключаться к GitHub как клиент через SSH, а в то же время принимать SSH-подключения от другого компьютера, если на нём запущен SSH-сервер.  

</details>


# 2. LAN, WAN, Internet.
<details>
### LAN

LAN (Local Area Network) — локальная сеть, объединяющая устройства на небольшой территории: например, дома, в офисе или компьютерном классе.

### WAN — глобальная сеть

**WAN (Wide Area Network)** — сеть, которая соединяет устройства или другие сети на больших расстояниях.  
Например, компания может объединить офисы в разных городах через WAN.  
LAN обычно охватывает небольшую территорию, а WAN связывает сети на больших расстояниях.  

### Internet

**Internet** - это глобальная система взаимосвязанных компьютерных сетей, которые обмениваются данными с использованием общих протоколов связи, прежде всего семейства TCP/IP.  

**Интернет** — это сеть сетей, объединяющая компьютеры, серверы, смартфоны и другие устройства по всему миру c помощью кабеля, оптики, wifi и другими каналами связи.  

</details>

# 3.Router, Switch, Modem, Access Point.
<details>

**1. Router — маршрутизатор**  

Router (роутер) — устройство, которое пересылает IP-пакеты между разными сетями.  

Например:  
- соединяет твою домашнюю LAN с сетью провайдера;  
- направляет запросы к удалённым серверам;  
- обычно выполняет NAT, позволяя нескольким домашним устройствам использовать один внешний IPv4-адрес.  
Пример: ноутбук хочет открыть example.com. Роутер помогает направить пакеты из домашней сети в сторону Интернета.  

**2. Switch — коммутатор**  

Switch (коммутатор) — устройство, которое соединяет устройства внутри локальной сети и пересылает Ethernet-кадры, ориентируясь на MAC-адреса.  

Например, к коммутатору подключены:  
- компьютер;  
- сервер;  
- принтер;  
- роутер.  

Коммутатор запоминает, за каким портом находится каждый MAC-адрес, и направляет кадры в нужный порт.  

Главное отличие: Switch соединяет устройства внутри LAN, а Router маршрутизирует трафик между IP-сетями.  

**3. Modem — модем**  

Modem (модем) — устройство, которое обеспечивает передачу данных через определённую технологию связи с сетью провайдера.  

Примеры:  
- кабельный модем — для кабельной сети;  
- DSL-модем — для телефонной линии;  
- сотовый модем — для мобильной сети.  

При оптоволоконном подключении обычно используется ONT/ONU — устройство, которое связывает оптоволоконную линию с Ethernet-сетью.  
Модем или ONT сам по себе не обязательно выполняет функции роутера.  

**4. Access Point — точка доступа**  

Access Point (AP, точка доступа) — устройство, которое позволяет беспроводным устройствам подключаться к локальной сети по Wi-Fi.  

Например, смартфон подключается к точке доступа по Wi-Fi, а она передаёт его трафик в проводную LAN.  

Точка доступа не обязательно маршрутизирует трафик между разными сетями — это зависит от устройства и его режима работы.  

```
Устройство     Основная задача                         Ориентируется преимущественно на
Router         Соединяет разные                        IP-сети	IP-адреса
Switch         Соединяет устройства внутри LAN         MAC-адреса
Modem          Обеспечивает связь с сетью провайдера   Технологию линии связи
Access Point   Подключает устройства по Wi-Fi          Беспроводное соединение и кадры LAN
```
**ip addr** — показывает сетевые интерфейсы и назначенные им IP-адреса.  
**ip route** — показывает маршруты, по которым система отправляет IP-пакеты.  

</details>

# 4. Как данные проходят от компьютера к серверу.  
<details>

1. Общая схема

```
1. Твой компьютер
Браузер формирует запрос
           ⮃
2. Домашний роутер
Направляет трафик в сеть провайдера
           ⮃
3. Интернет
Маршрутизаторы передают пакеты между сетями
           ⮃
4. Сервер example.com
Обрабатывает запрос и отправляет ответ
```
Стрелки в обе стороны: запрос идёт к серверу, ответ возвращается к компьютеру  

</details>

2. 2. Что происходит по шагам
<details>
a) DNS — находим IP-адрес сервера  
   Ты вводишь example.com, но компьютеру для отправки пакетов нужен IP-адрес назначения. DNS помогает преобразовать доменное имя в IP-адрес.  

b) Routing — выбираем путь  
Компьютер проверяет свою таблицу маршрутизации. Если сервер находится за пределами домашней сети, пакет обычно отправляется через шлюз по умолчанию — домашний роутер.  

В Linux посмотреть маршруты можно командой:  
`ip route`

c) TCP — устанавливаем соединение  

Для HTTPS обычно используется TCP-порт 443. Компьютер и сервер устанавливают TCP-соединение, обмениваясь служебными пакетами. Этот процесс называется трёхсторонним рукопожатием (three-way handshake).  

d) TLS — защищаем соединение  
Клиент и сервер согласовывают параметры защищённого соединения и проверяют сертификат сервера. После успешного установления TLS данные HTTPS передаются в зашифрованном видеTLS — защищаем соединение  
Клиент и сервер согласовывают параметры защищённого соединения и проверяют сертификат сервера. После успешного установления TLS данные HTTPS передаются в зашифрованном виде.  

e) HTTP — отправляем запрос 
Браузер отправляет HTTP-запрос, например запрос на получение главной страницы сайта. Сервер принимает его и обрабатывает.  

f) 1. Ответ возвращается обратно  
Сервер отправляет HTTP-ответ: статус, заголовки и, например, HTML-код страницы. Компьютер принимает данные, а браузер отображает сайт.  

**Важно:** это типичная последовательность для HTTPS поверх TCP. **HTTP/3** работает иначе: он использует QUIC поверх UDP, а не TCP.  
</details>

3. Как данные физически передаются.  
<details>
Вот важная концепция для Linux Networking: данные разбиваются на небольшие части и передаются в виде сетевых пакетов.  

```
                  Данные приложения
                     HTTP-запрос
                         ⬇
                     TCP-сегмент
     Добавляется информация TCP, включая порты
                         ⬇
                      IP-пакет
     Добавляются IP-адреса источника и назначения
                         ⬇
          Ethernet-кадр или Wi-Fi-кадр
     Данные для передачи по локальному каналу
                         ⬇
                   Биты по сети
     Электрические, оптические или радиосигналы
```

Это называется **инкапсуляцией**: каждый сетевой уровень добавляет свою служебную информацию. На принимающей стороне она постепенно обрабатывается, чтобы приложение получило исходные данные.  

Обрати внимание: Ethernet-кадр обычно относится только к текущему участку сети. При переходе через роутер кадр формируется заново, а IP-пакет обычно продолжает путь к тому же адресу назначения.  

Запомнить:
```
Термин       Роль
DNS          Находит IP-адрес по доменному имени
IP           Обеспечивает адресацию и доставку пакетов между сетями
Router       Выбирает следующий участок пути для пакета
TCP          Обеспечивает надёжную передачу данных
TLS          Защищает соединение шифрованием
HTTP/HTTPS   Протокол обмена данными между клиентом и веб-сервером
Port         Помогает доставить данные нужному сетевому приложению
```
</details>
