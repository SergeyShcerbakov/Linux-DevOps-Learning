## 1. What is AWS?

**AWS (Amazon Web Services)** — облачная платформа Amazon, предоставляющая вычислительные ресурсы, хранилища, базы данных, сети и другие IT-сервисы через интернет.

<details>
Вместо покупки и обслуживания собственных серверов можно арендовать ресурсы AWS и управлять ими по мере необходимости.

**Пример:**
- Раньше: купить физический сервер, установить ОС, настроить сеть и обслуживать оборудование.
- С AWS: создать виртуальный сервер EC2 через консоль или AWS CLI и оплачивать используемые ресурсы.
</details>

## 2. What is Cloud Computing?
<details>
**Cloud Computing (облачные вычисления)** — предоставление вычислительных ресурсов и IT-сервисов по требованию через сеть.

Основные преимущества:  
- **On-demand:** создавать ресурсы по мере необходимости.  
- **Scalability:** увеличивать или уменьшать ресурсы.  
- **Elasticity:** автоматически адаптировать ресурсы к текущей нагрузке.  
- **Pay-as-you-go:** платить за использование согласно тарифам.  
- **High Availability:** повышать доступность благодаря резервированию.  
- **Global Reach:** развёртывать приложения в разных регионах мира.  

Важно: облако не означает, что физических серверов нет. Серверы существуют в дата-центрах поставщика, например Amazon.
</details>
## 3. Cloud Service Models (IaaS, PaaS,SaaS)
<details>

### IaaS — Infrastructure as a Service

Поставщик предоставляет базовую инфраструктуру: виртуальные машины, сети и хранилища. Пользователь управляет ОС и установленным программным обеспечением.

**AWS example:** EC2.

### PaaS — Platform as a Service

Поставщик управляет большей частью инфраструктуры и платформы, чтобы разработчик мог сосредоточиться на приложении.

**AWS example:** Elastic Beanstalk — сервис развёртывания приложений, который автоматизирует многие инфраструктурные задачи.

### SaaS — Software as a Service

Готовое приложение, доступное пользователю через интернет. Пользователю не нужно самостоятельно устанавливать и обслуживать его серверную инфраструктуру.

**Examples:** Gmail, Microsoft 365.

`Примечание:` AWS предлагает сервисы с разными уровнями управления. Не каждый сервис AWS строго относится только к одной модели.

</details>
## 4. Cloud Deployment Models
<details>

- **Public Cloud:** инфраструктура предоставляется облачным провайдером многим клиентам. Пример — AWS.
- **Private Cloud:** облачная инфраструктура выделена для одной организации.
- **Hybrid Cloud:** сочетание собственной инфраструктуры или частного облака с публичным облаком.

</details>

## 6. Shared Responsibility Model
<details>
**Shared Responsibility Model** — модель разделения обязанностей по безопасности между AWS и клиентом.

### AWS is responsible for security OF the cloud
<details>
AWS отвечает за безопасность самой облачной инфраструктуры:  
- физические дата-центры;  
- физические серверы и оборудование;  
- базовая инфраструктура сети;  
- безопасность облачной платформы.  
</details>

### Customer is responsible for security IN the cloud
<details>
Клиент отвечает за безопасность своих ресурсов и данных в соответствии с выбранными сервисами:  
- управление доступом через IAM;  
- настройка сетевых правил;  
- защита данных и управление шифрованием;  
- настройки ОС и обновления на EC2;  
- безопасная конфигурация приложений.  

**Важно:** распределение ответственности зависит от сервиса. Например, при использовании EC2 клиент управляет гостевой ОС, а при использовании управляемой базы данных RDS часть задач по обслуживанию ОС выполняет AWS.
</details>

</details>

## 7. AWS Account and Billing
<details>

- **AWS Account:** аккаунт, в котором создаются ресурсы и настраиваются доступ и биллинг.  
- **AWS Management Console:** веб-интерфейс для управления ресурсами.  
- **AWS CLI:** командная строка для управления AWS.  
- **AWS SDK:** библиотеки для работы с AWS из программного кода.  
- **Billing:** учёт расходов за использование сервисов.  
- **AWS Budgets:** настройка бюджетов и уведомлений о расходах.  
- **Cost Explorer:** анализ затрат и их динамики.  

Важно: создание ресурса не всегда бесплатно. Перед запуском проверяй тарифы, регион, объём хранения и условия Free Tier.

</details>

## 8. Basic AWS Workflow
Пример типичного сценария развёртывания веб-приложения:
<details>
1. Создать VPC и подсети.  
2. Настроить маршрутизацию и сетевой доступ.  
3. Создать EC2 для приложения.  
4. Настроить IAM с минимально необходимыми разрешениями.  
5. Разместить статические файлы в S3, если это нужно приложению.  
6. Настроить базу данных RDS при необходимости.  
7. Использовать ELB для распределения трафика, если требуется.  
8. Настроить CloudWatch для мониторинга.  
9. Проверять расходы через Billing и Cost Explorer.  

Это пример архитектуры, а не обязательная последовательность для каждого приложения.
</details>

## 9. Key Terms/ключевые термины

<details>
- **Resource:** созданный облачный объект, например EC2 instance или S3 bucket.
- **Region:** географический регион AWS.
- **Availability Zone (AZ):** изолированная группа инфраструктуры внутри региона.
- **Scalability:** способность системы увеличивать или уменьшать доступные ресурсы.
- **Elasticity:** адаптация ресурсов к изменению нагрузки.
- **High Availability (HA):** обеспечение доступности сервиса при отдельных сбоях.
- **Fault Tolerance:** способность продолжать работу при определённых отказах.
- **IAM:** управление идентификацией и разрешениями.
- **Least Privilege:** предоставление только тех разрешений, которые необходимы для задачи.
- **Infrastructure as Code (IaC):** управление инфраструктурой с помощью описаний в коде, например Terraform или AWS CloudFormation.
</details>
