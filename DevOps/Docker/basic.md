# 1. то такое Docker и зачем он нужен
<details>

**Docker** — это инструмент, который позволяет запускать приложения в изолированных контейнерах.  
Проще:  
«Ты упаковываешь программу вместе со всеми зависимостями и запускаешь её где угодно одинаково»  

</details>

# 2. Проблема: “у меня работает, у тебя нет”
<details>

```
Это классика разработки:  
у тебя Python 3.10 → всё ок  
у другого Python 3.8 → уже ошибка  
разные библиотеки, версии, конфиги  
```

➤ **Docker решает это так:**
`создаётся одинаковое окружение
у всех запускается один и тот же контейнер`
</details>

# 3. Образ vs Контейнер различия
<details>

```
**Docker Image** (образ)         — шаблон приложения, содержащий код, зависимости и необходимые файлы для запуска контейнера. Неизменяемый исходный шаблон.  
**Docker Container** (контейнер) — запущенный или остановленный экземпляр образа с собственным изолированным окружением и записываемым слоем.
```
Контейнер (Container)-это «запущенный образ»

```
образ = файл           образ = .iso 

контейнер = процесс    контейнер = запущенная система
```
**Процесс** — это выполняющаяся программа, которой операционная система выделила ресурсы для её работы.  

```
docker pull nginx          # Скачать образ
docker run -d nginx        # Создать и запустить контейнер
docker ps                  # Показать запущенные контейнеры
docker ps -a               # Показать все контейнеры
```
**Контейнеры эфемерные:**
удалил контейнер → данные могут пропасть (если нет volume)

Где хранятся изменения:
изменения идут в верхний слой контейнера, образ остаётся неизменным.

`**Главное:** один образ может использоваться для создания нескольких контейнеров.`

</details>

# 4. Жизненый цикл контейнера & Архитектура Docker: Client → Daemon → Container
<details>

##**Жизненный цикл контейнера**

```
- Created    — контейнер создан, но не запущен.
- Running    — контейнер работает.
- Paused     — выполнение приостановлено.
- Restarting — контейнер перезапускается.
- Exited     — контейнер остановлен.
- Dead       — контейнер не смог корректно завершить переход в другое состояние.
```

Основные команды: docker create, docker start, docker pause, docker unpause, docker stop, docker restart, docker rm  

##**Архитектура Docker: Client → Daemon → Container**

```
- Docker Client           — принимает команды пользователя (docker run, docker ps).
- Docker Daemon (dockerd) — обрабатывает запросы, управляет образами, контейнерами, сетями и томами.
- Container               — изолированная среда, в которой выполняется приложение.
```

</details>

# 5. Docker Engine, Docker CLI, Docker Daemon
<details>

Как работает: Client отправляет запрос → Daemon обрабатывает его → создаёт или управляет контейнером.  

**CLI** (Command Line Interface)  
`ты → Docker CLI → Docker API → Docker Daemon → containerd → контейнер`

**Важное понимание**
CLI можно вообще не использовать можно отправлять команды 
напрямую через API (например через curl) 
```
Docker Desktop и GUI — это тоже просто клиенты к Engine
Docker CLI           — это инструмент, через который ты вводишь команды
Docker Engine       — это сервис (демон), который: принимает команды управляет контейнерами
```
**CLI отправляет команды в Docker Engine через API, 
а Engine уже создаёт и управляет контейнерами.**

Docker Engine -Это «движок», который запускает контейнеры

</details>
